## 分析原则

- 下载范围覆盖全部历史；正式分析范围根据质量、口径和研究问题讨论确定。
- 天气优先采用 O’Hare `USW00094846` 的 Daily Summaries，Midway `USW00014819` 作为备选；按作业要求获取降水、降雪、积雪、风速和温度，并检查缺失与质量标记。
- 历史站点优先依据同期资料和行程记录整理；当前 GBFS 快照单独注明获取时间，不用于直接重建历史站点。
- 清洗保留处理理由和前后记录数；区分缺失与零，不因站点信息缺失而统一删除全部相关行程。
- 区分疫情、系统扩张、字段变化与行为规律，避免跨时期直接比较产生误导。
- 天气分析优先使用每日汇总；统计推断考虑时间相关性，不能把同一天的每条行程视为独立天气样本。
- 选择方法时考虑季节、星期、温度等混杂因素；关联结果不直接解释为因果。
- 若采用留出年份验证，在相关探索开始前确定划分；假设未获支持也如实报告。

## 交付与协作

- 全部代码使用根目录 uv 项目及 `.venv/`，提供明确的运行入口。
- 原始数据保存在服务器，不推送至 GitHub；提交下载清单和复现代码，记录来源与版本。
- 持续记录 AI 的建议、编程和分析，以及用户实际作出的判断，不将 AI 发现记作用户独立发现。
- 报告详细呈现过程；汇报围绕“问题—发现—验证—结论”，重点使用一张发现图和一张验证图。
- 完整报告的具体格式在撰写前确认；页数与版式在核心图表确定后安排。
- 用户在 GitHub 合并 PR 后，同步主分支，并清理对应的已合并本地分支。
